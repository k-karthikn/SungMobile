# Stage 8 plan — continuous and advanced online playback

Prepared 18 October 2026 for owner review, then authorized for implementation. The owner confirmed `0.8.1-online`, code 13, and the Stage 8 code 14 build work on the POCO. Stage 8's implementation and capability limits are recorded in `STAGE8_REPORT.md`. Stage 7 device music and downloads remain deferred. Stage 8 uses YouTube as the only music source, keeps the current app ID `com.karthi.sungmobile.stage0`, signing certificate and phone data, and continues the manual APK-testing workflow.

## Intended result

Reduce avoidable silence between queued songs, then add carefully bounded optional playback enhancements: crossfade, loudness adjustment, smart shuffle and related-song autoplay. Keep one service-owned playback authority and the existing queue, media session, sleep timer, lyrics clock and saved-session behavior. Use small M3 Expressive controls within the existing screens; this is not a design-polish pass. Do not add device-file access, downloads, sign-in or another online music provider.

The current coordinator resolves a signed stream only when activating a song, and the engine replaces its sole MediaSource for each item. That makes network resolution part of every transition. Media3 supports playlists and a preload manager, but its preload manager expects the player to be built from the same builder; adopting it is an architectural choice to verify against the current single service-owned player. [Media3 playlists](https://developer.android.com/media/media3/exoplayer/playlists), [Media3 preload manager](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager), [preload manager lifecycle](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager/concepts).

## Proposed behavior and defaults

1. **Next-track preparation:** Prepare at most the next queue occurrence while the current song is actively playing. Resolve its YouTube stream shortly before it is needed, and optionally prebuffer a small bounded portion if a same-player path proves safe. Never persist signed URLs or media bytes as a download. Discard preparation on queue replacement, edit that changes the successor, manual jump, Stop, service release, stale/expired URL, or repeat/timer mode that changes the next action. Pausing must not start another track. Prefer a Wi-Fi-only prebuffer default; mobile data may still resolve the next track without downloading audio ahead of time. The exact time/byte caps will be set from measured POCO data before implementation is accepted.
2. **Transition and gapless claim:** First make the normal end-of-song handover use a ready next item where possible. Test supported YouTube stream formats and actual encoded transitions on the POCO. Do not remove intentional silence from recordings or call every transition “gapless.” If the source lacks reliable gapless information, show no gapless guarantee. Preserve duplicate queue occurrence IDs, repeat-one/all, manual Next and the sleep timer's end-of-track/end-of-queue rules.
3. **Crossfade:** Separate off-by-default setting, proposed choices 3, 5 or 8 seconds. It starts only for a natural transition between two ready, finite-duration songs when both can be safely decoded. Manual Next, seeking near the end, a pending end-of-track sleep timer, unknown duration, errors and unsupported outputs use the ordinary handover. Pause/focus loss/Stop during an overlap silence both streams; cancel or switch restores normal gain. Overlapping audio may require a second decoder inside the *same service*, so this part has a feasibility gate: if resource use or session correctness is poor on the POCO, ship the stable non-overlap transition and record crossfade as limited rather than adding a fragile second playback owner.
4. **Loudness and trim:** Keep automatic normalization off by default. First check whether the available YouTube stream metadata yields a reliable per-track loudness value. Apply a bounded adjustment only with trustworthy data; otherwise do not label a heuristic as normalization. Offer a separate manual per-song trim (proposed range −6 to +6 dB, default 0) keyed to canonical video ID. Combine trim/normalization, crossfade and the existing sleep-timer fade in one gain calculation, capped to avoid clipping or a volume jump. Never change system volume. Media3 has audio gain-processing APIs, but their compatibility with SungMobile's stream formats and output modes must be tested before choosing the implementation. [Media3 GainProcessor](https://developer.android.com/reference/androidx/media3/common/audio/GainProcessor).
5. **Smart shuffle:** Keep ordinary shuffle intact. Add an off-by-default smart option that best-effort separates repeated songs and artists when enough distinct entries exist, without deleting duplicate occurrences or changing the saved original order. Queue edits and Undo remain deterministic. A fixed test seed should reproduce ordering in host tests; the user still sees and can edit the actual queue.
6. **Related autoplay:** Off by default. Only after a natural queue end with repeat off, request related YouTube songs from a verified provider capability. Use the finishing song as the seed; Private mode must not use listening history for personalization. Filter duplicates and unavailable items, make one bounded recommendation request, and stop after a small bounded number of failed candidates. If the adapter cannot return reliable related songs, keep the setting unavailable and leave the ordinary stop-at-end behavior. Do not invent a “related” list from unrelated search results.

Settings persist separately from saved queue snapshots. Cold restoration stays paused and starts no preload or autoplay request until the user plays. Turning an option off takes effect immediately; no stale fade, gain or recommendation task may survive it. Existing speed/pitch, lyric timing, audio focus, lock-screen controls, playback notification and timer behavior remain authoritative.

## POCO acceptance proposal

1. Install the Stage 8 APK over code 13 without uninstalling. Confirm Likes, playlists, lyrics settings, saved sessions and paused queue restoration survive.
2. Play a short queue on Wi-Fi and mobile data. Listen to several natural transitions and compare them with code 13. Skip, pause, seek near the end, reorder and remove the next entry while preparation is active; the correct song must play once.
3. Test repeat off/all/one, shuffled duplicates, manual Next, the end-of-track and end-of-queue sleep timers, screen lock, headset disconnect and an audio-focus interruption. No obsolete item or fade may play afterward.
4. If crossfade passes its feasibility gate, try each duration, pause and skip during overlap, then turn it off. Check normal volume afterward. If normalization or manual trim is available, compare quiet and loud tracks and verify the timer fade still restores volume.
5. Enable smart shuffle and inspect the actual queue. Enable related autoplay, let the queue finish, then repeat in Private mode and with network unavailable. Turn autoplay off and confirm normal stop-at-end behavior.
6. Compare battery/data use and memory with code 13 during a realistic listening session. Record any device- or stream-format-specific limitations instead of claiming universal gapless or normalization support.

No Stage 8 APK or code change is authorized by this plan alone; the document is ready for owner review. The order deliberately lets transition reliability stand on its own if crossfade, normalization or related autoplay fail their capability gates.
