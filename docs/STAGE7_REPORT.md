# Stage 7 — device music and visible downloads

Prototyped 18 October 2026 as `0.8.0-stage7`, version code 12. Stage 6 code 11 is accepted on the owner's POCO. **The owner deferred Stage 7 before phone acceptance.** Its source is preserved in `deferred/stage7/` outside the active build. The active code 13 app is online-only. The assistant did not install or test code 12 on the phone.

## Delivered behavior

- Library opens **Device music** and **Downloads**. The device view scans shared `Music/` and its subfolders by default after audio permission. The user can turn that default off, add included or excluded folders with Android's picker, choose automatic scanning or **Scan now**, and filter the indexed songs. An excluded or removed folder is hidden from the scan; the app never deletes source files. Indexed entries that disappear remain marked unavailable.
- Device songs use `content://` identities and the existing Media3 playback service. They can play, queue, join Likes and playlists, be found by title/artist in Search, and be saved in sessions. Local content does not go through the YouTube resolver. A missing file fails as unavailable instead of selecting another song.
- YouTube songs have a Download action in song menus and Now Playing. Collection downloads require a confirmation after page loading. Background jobs resolve a new YouTube audio URL per attempt, track bytes and state in Room, obey a default Wi-Fi-only policy and a configurable download budget, and retry interrupted network transfers from the beginning. No signed stream URL is stored.
- On Android 10+, the default finished destination is shared `Music/SungMobile/` through `MediaStore`. A pending file is published only after a complete transfer and audio-duration validation. The user can select another supported device or SD-card folder for future downloads. A completed file can be opened by a file manager or other music app and used by SungMobile without network access. Cancelling, retrying and deleting an owned download are available in Downloads; deletion asks first and leaves Likes, playlists and history intact. Changing the destination does not move earlier files.
- Room migration 2→3 adds separate device-track, folder-rule and download-inventory tables. It does not rewrite existing library or queue rows. The app ID remains `com.karthi.sungmobile.stage0`, and the debug signing certificate matches accepted code 11, so this is an in-place update.

## Verification and limits

The offline host suite passed **139 tests**, with six opt-in live-provider probes skipped and zero failures. Tests include the 2→3 migration and local track identity. `lintDebug` passed with zero errors, and `assembleDebug` produced the signed APK. The package metadata and certificate were checked against code 11. The APK and manual checklist are in `Stages/Stage7_Results/`.

Phone behavior remains unverified. In particular, confirm the POCO's permission prompt, MediaStore visibility, folder picker, background transfer and airplane-mode playback before accepting Stage 7. Android 8–9 require a user-selected writable download folder; the shared `Music/SungMobile/` default uses Android 10+ MediaStore. Arbitrary SAF folders refresh on opening the device view or by **Scan now**; there is no background periodic scan. The scan reports its found-file count and an access error where applicable, but not an added/changed/missing breakdown. Partial transfers restart rather than resume bytes, because a fresh stream cannot prove byte identity. Automatic keep-played caching remains off and was not added.
