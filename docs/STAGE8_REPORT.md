## Delivered behavior

- While a finite-duration track is playing and within 45 seconds of its reported end, the service resolves at most one next queue occurrence's signed YouTube URL. Natural completion uses it only if its occurrence still matches and the URL has over two minutes of validity margin. Otherwise ordinary resolution handles the transition. It holds one URL in memory, downloads no audio ahead of time, and persists neither the URL nor media bytes. Pause, Stop, manual Next, seek, repeat/shuffle changes, queue edits and service release discard obsolete preparation. One failed preparation is not retried repeatedly during the same track.
- Smart shuffle is off by default. When enabled, it reorders upcoming occurrences to separate repeated song IDs and artists where possible; played entries and duplicate occurrence identities remain. The actual queue stays editable, and the original order remains available when Shuffle is turned off.
- Per-song manual volume reduction is off by default (0 dB) and can be adjusted to −12 dB in 1 dB steps. It is keyed to the canonical YouTube video ID, stored in DataStore, and multiplied with the sleep timer fade before applying player volume. It never changes system volume. Positive boost is omitted to avoid claiming headroom the current player volume API cannot provide.
- Related autoplay is off by default. At a natural queue end with repeat off, and only if the sleep timer does not stop playback, one request uses NewPipeExtractor's provider-supplied `StreamInfo.relatedItems` for the finishing song. It filters duplicate/current IDs, non-song items, invalid links and duration outliers, and adds at most five new queue entries. A failed or empty request ends normally. Private mode suppresses this request; no listening history is used to choose a seed.

The existing YouTube-only source, one service-owned player, queue persistence, speed/pitch, lyrics, saved sessions, lock-screen controls and sleep timer remain in use. Stage 7 device audio and downloads remain outside build source sets. Room schema stays at version 4, so no data migration or new permission is required. The APK keeps app ID `com.karthi.sungmobile.stage0` and debug certificate SHA-256 `137475c127f1805b413c4362ddd69573e41f70c3cde76fd38a1bf5ebabfbe850` for an in-place update.

## Capability limits

The current NewPipe `StreamInfo` API exposes duration, stream formats and related items, but no reliable per-track integrated loudness value. Automatic normalization is therefore absent. Crossfade would require a safely synchronized second decoder with focus, session, speed, seek and timer behavior; that path was not validated on the POCO, so no crossfade control is exposed. The engine still replaces a single MediaSource at each transition. Prepared URL resolution can remove extraction wait, but it does not prebuffer audio or guarantee a gapless handover. Actual transition gaps, byte use, battery and related-feed quality require the owner's manual POCO test. Related candidates are provider results, not a guarantee that every item is a music recording; failed playback does not cascade through more candidates.
