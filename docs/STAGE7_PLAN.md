# Stage 7 plan — device music, visible downloads and offline playback

Revised: 18 October 2026 after owner feedback; prototyped as `0.8.0-stage7`, code 12. **Deferred by the owner before phone acceptance.** The active code 13 app is online-only. This document is retained for later consideration, not an active implementation plan. See [the online-only report](ONLINE_ONLY_REPORT.md).

## What the owner requested

- Save completed downloads in user-visible device storage so other music apps and file managers can see them.
- Show audio from the device's `Music/` folder by default, including its subfolders. Let the user add or remove included folders and exclude subfolders.
- Offer automatic discovery and a **Scan now** action. Let the user change the default scan location and the destination for new downloads.
- Keep the existing app ID `com.karthi.sungmobile.stage0`, signing key and phone data. Continue with simple M3 Expressive screens, focused files and manual APK testing.

## Android storage approach

The default download destination is **shared `Music/SungMobile/`**, not an app-private directory. On Android 10+ use `MediaStore.Audio` with `RELATIVE_PATH` and keep a new item pending until the audio is complete and validated; publishing it makes the file visible to other apps. The owner can choose another supported folder through Android's folder picker, with persisted access. Temporary transfer data may be private while a download is incomplete; the finished file lives in the chosen shared destination. Files in shared media storage remain on the device if SungMobile is uninstalled. [Android shared media guide](https://developer.android.com/training/data-storage/shared/media), [MediaStore media columns](https://developer.android.com/reference/android/provider/MediaStore.MediaColumns).

On first use of the local library, ask for audio access. Android 13+ uses `READ_MEDIA_AUDIO`; older supported versions use the applicable legacy media permission. If permission is declined, YouTube features remain usable and the app explains why the default `Music/` scan is unavailable. A separately selected folder can be read through a persisted Storage Access Framework (SAF) grant. Android 11+ does not let the folder picker grant access to storage roots, `Download/`, or `Android/data`; show that limitation when a user tries to select such a location. Do not request all-files access. [Android 13 media permissions](https://developer.android.com/about/versions/13/behavior-changes-13), [SAF directory access](https://developer.android.com/training/data-storage/shared/documents-files).

`Music/` is a user-visible shared-storage location, not a hard-coded absolute path. Query `MediaStore` by content URI and relative location; do not build file paths from `RELATIVE_PATH`. The same rule applies when opening local audio for playback. [MediaStore media columns](https://developer.android.com/reference/android/provider/MediaStore.MediaColumns).

## Proposed defaults and behavior

1. **Local folder set:** Include `Music/` and its subfolders by default once permission is granted. The user can remove or replace that default, add other folders with the system picker, and exclude a chosen subfolder from an included tree. Show each rule and whether its access still works. Excluding a folder hides it from SungMobile scans; it never deletes files. If a folder is removed or access is revoked, keep playlist entries as unavailable until the user restores access or removes them.
2. **Scanning:** Auto scan at app start/resume and after relevant indexed-media changes, with debounce so large libraries do not repeatedly rescan. SAF folders are refreshed on app start/resume and by **Scan now**; optional periodic background refresh can be added only if it proves reliable on the POCO. Manual scan reports added, updated, missing and unsupported files. Do not claim instant monitoring of arbitrary SAF folders. Scan recursively within included folders, apply exclusions before indexing, and skip non-audio or undecodable files with an explanation.
3. **Local playback and library:** Local audio can be searched and played, queued, liked, added to local playlists and included in saved sessions. Keep a typed local identity and `content://` source separate from YouTube video IDs and signed stream URLs. Do not send local files to the YouTube resolver or treat a filename as a YouTube link. Existing queue occurrence IDs still distinguish duplicates. Local listening obeys the same history and Private mode rules. Missing or moved files show an unavailable state and an explicit rescan/relink path rather than silently playing a different file.
4. **Downloads:** Show Download, Cancel, Retry and Remove for supported YouTube songs. The default destination is `Music/SungMobile/`; changing it affects future downloads and does not move existing files without a separate explicit action. A completed download is indexed as an owned device file and shared across duplicate occurrences of its YouTube song. Keep a durable mapping from video ID to the owned media URI, while also allowing the file to appear in the local-device view without a duplicate row. A user can still play a completed file after uninstalling SungMobile through another app.
5. **Safety and storage:** Never expose a partial transfer as a finished song. Stage files or use MediaStore's pending state, validate before publishing, and reconcile interrupted writes after restart. On a user-selected SAF destination, publish a final file only after a complete copy and validation, and clean up failed partial documents. Keep the proposed **2 GiB** explicit-download budget and **256 MiB** free-space reserve as editable defaults; never silently delete an intentional download to meet the budget. Removing an owned download must explain that it deletes that device file; removing a local-library reference never deletes the user's own file.
6. **Network and optional cache:** Wi-Fi-only downloads are on by default; mobile data requires an explicit change. Jobs pause visibly when the selected policy is not met. Automatic keep-played caching stays off and separate from user-visible downloads; if later enabled, cap it at **250 MiB** and do not present its entries as durable downloaded songs. YouTube remains the only network music provider. Optional LRCLIB lyrics fallback stays under the existing setting; local files have no fabricated synced lyrics.

## Proposed POCO checks

1. Upgrade over code 11 without uninstalling; verify existing Likes, playlists, lyrics settings, saved sessions and queue.
2. Grant audio access. Confirm `Music/` and nested audio appear; exclude one subfolder, run **Scan now**, then include it again. Add a different folder and change the default scan location. Revoke one folder grant and check the visible explanation.
3. Play a local song in airplane mode; add it to a playlist, queue it twice, seek, use speed/sleep timer, then restart and restore the queue paused.
4. Download a YouTube song to `Music/SungMobile/`; confirm it appears in the phone's file manager/another music app and plays in airplane mode. Change the destination for a second download and confirm the first file stays where it was.
5. Cancel/retry a download, interrupt one by closing the app or changing Wi-Fi, and verify no partial file is reported as playable. Remove an owned download and confirm SungMobile explains that the device file will be deleted, while Likes/playlists remain.

The prototype used a 2 GiB default download budget and a 256 MiB free-space reserve. The optional 250 MiB automatic cache was not implemented. Stage 7 was deferred before phone acceptance; the online-only Stage 8 plan is now in `STAGE8_PLAN.md` for review.
