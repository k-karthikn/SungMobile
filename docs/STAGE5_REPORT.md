# Stage 5 — lyrics and essential settings

Implemented 18 October 2026. Host checks passed; the owner reported the updated Stage 5 app working on the POCO and accepted Stage 5 on 18 October 2026. The APK and checklist are under `Stages/Stage5_Results/`.

## Delivered behavior

- Now Playing opens a separate lyrics screen backed by the existing playback controller. It shows source attribution and actual YouTube Music lyrics when the anonymous lyric tab is available. The Android app fetches a timed mobile response first, then a plain web response; it never assigns artificial timestamps to plain text. Timed lines highlight against playback position and can seek when the track is seekable. Dragging stops automatic following until **Return to current line** is tapped. Timing offsets are saved by canonical YouTube video ID, bounded to ±10 seconds.
- LRCLIB is an optional lyrics-only fallback, off by default. It runs when YouTube yielded no lyrics or only plain lyrics and Private mode is off. A strictly matched timed LRCLIB result may upgrade plain YouTube text; an LRCLIB plain result does not replace existing YouTube text. Lookup sends title, artist and duration. Results require normalized exact title/artist, duration within two seconds, and substantive lyric content; ambiguous or tiny submissions are rejected. Rate limits pause new LRCLIB lookups for a minute. Source is labeled LRCLIB.
- Settings add LRCLIB consent, lyric text size, a lyric-cache switch, scoped cache clear, About, the full app GPL license and third-party notices. Saved lyric text uses a private 8 MiB/30-day bounded cache. Turning caching off clears it. Cache clearing does not touch Room library/queue/history or saved offsets. The existing theme/color/reduced-motion settings remain.
- Network requests have fixed HTTPS hosts, size and time limits, and cancellation. A track switch invalidates the old lyrics request. Neither lyric lookup nor cache writes listening/search history. There is no Google sign-in or second music source.

## Code 9 follow-up (0.6.1-stage5)

The owner reported that a search result for an original song had timed lyrics while a differently named playlist entry for apparently the same song had plain or no lyrics. Catalog entries use each YouTube item's own URL and metadata; differently named entries may be different video IDs, and exact LRCLIB matching can reject the alternate title. We cannot infer that both entries refer to the same recording without evidence. The Stage 5 implementation also had a recoverable gap: it queried LRCLIB only when YouTube returned nothing, so an enabled fallback could not improve a plain YouTube result. Code 9 queries LRCLIB for plain or missing YouTube lyrics, selects a strictly matched timed result when available, and otherwise retains YouTube plain text. The parser also preserves untimed lyric rows from mobile YouTube responses, including mixed cue availability, instead of losing them. If the web browse call fails after obtaining mobile plain text, that mobile result remains available. No artificial timestamps are assigned.

The full offline host suite, lint and debug APK build passed. Lint reported zero errors and 13 dependency/version notices. APK `0.6.1-stage5`, code 9, has the same app ID and debug signing certificate as code 8. The owner subsequently reported everything working fine and accepted Stage 5. This was a general phone acceptance report; individual checklist outcomes were not separately recorded.
