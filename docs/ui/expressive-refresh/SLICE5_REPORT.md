# Expressive UI refresh: Lyrics, loading and settings

24 October 2026. This completes slice 5 of [PLAN.md](PLAN.md). It was initially implemented source-only; later the same day all five slices were packaged in [production candidate `0.12.6` (code 26)](../../../Stages/Expressive_UI_Results/README.md). No APK was installed or phone tested by Codex.

Lyrics now keeps the active line near the reading area instead of snapping it to the top, with extra breathing room at the start and end. The active line has a clearer surface and explicitly uses Sung's Google Sans Flex theme typography. The header identifies real synced versus plain lyrics; the source/track card remains, and the timing offset controls occupy one compact row with accessible 0.25-second steps. Manual scrolling still exposes “Return to current line”; tap-to-seek still accounts for the saved offset. The reference's floating line timestamp and word-by-word styling were intentionally omitted: only line timing is available, and the owner specifically excluded the timestamp.

Home, Library, Mixes, collection operations, cleanup, history settings and Lyrics now use the shared native Material 3 expressive loading indicator for indeterminate waits. The shared helper presents a static readable label when motion is reduced. The mini-player's resolving/buffering control uses the native indicator within its existing button; its static reduced-motion symbol remains. Determinate playback progress is unchanged.

Settings switches use one full-row accessible layout with supporting explanations across Appearance, lyrics, updates and History & privacy. Theme/color choices use the same group surface. History's clear actions remain available. The mini-player and song menus use a shared checked item treatment with both tint and a check icon for Like, Shuffle and Repeat, while retaining their existing actions. No new product feature, source, permission, database change, package name, signer or version change was introduced.

Verification: focused Lyrics UI interaction test covers offset, manual-scroll return and tap-to-seek. All 90 debug unit tests, Kotlin compile and lint passed offline on the host; `git diff --check` passed. The later code-26 optimized release build and release lint passed, and its signer matches code 25. Phone visual and playback acceptance remains with the owner.

**24 October visual correction:** After reviewing code 26 on the phone, the owner requested no filled active-line background and a two-tone typography treatment like the reference. Code 27 removes the capsule and side bar; the active line uses `onSurface` plus selected word accents in the current theme's `primary` color. The accents are static typography, never a claim of word-level synchronization. Provider attribution no longer duplicates “Source:”. The mini-player, main Now Playing control and Queue peek now reuse one expressive play/pause button with the same icon transition and loading state. The reference's floating timestamp remains excluded. See the [code-27 delivery](../../../Stages/Lyrics_Emphasis_Results/README.md); phone acceptance is pending.
